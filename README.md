# 코니춘 팀 점심 도우미

코니춘 6장에서 만든 팀 점심 도우미를 **내 컴퓨터에서 실행하는 독자용 실습 코드**입니다. 팀원 입력 화면과 막내 비교 화면을 나누고, 가상 식당 A·B·C·D로 조건 비교와 확인 질문을 시험합니다.

ChatGPT·Sites·Cloudflare 계정, AI API 키, 유료 서비스가 필요하지 않습니다. 실행 중 AI를 호출하거나 식당을 검색하지 않습니다. 식당과 팀원은 모두 가상이며, 실제 식당의 정보가 아닙니다.

## 1. 준비하기

[Node.js](https://nodejs.org/) **22.22.0 이상**을 설치합니다. 터미널 또는 PowerShell에서 `node --version`으로 버전을 확인할 수 있습니다.

이 페이지 위쪽 **Code → Download ZIP**을 눌러 내려받고 압축을 풉니다. Git을 쓴다면 아래 명령도 가능합니다.

```sh
git clone https://github.com/jsbang01357/CNC_Lunch.git
cd CNC_Lunch
```

## 2. 실행하기

압축을 푼 폴더에서 터미널을 열고 실행합니다.

```sh
npm start
```

외부 패키지가 없어 `npm install`은 필요하지 않습니다. Node.js의 기본 기능만 사용합니다.

- Windows: 폴더의 `점심도우미_실행.cmd`를 두 번 눌러도 됩니다.
- macOS: `점심도우미_실행.command`로도 실행할 수 있습니다. 실행이 막히면 터미널에서 위 명령을 사용합니다.
- 종료: 실행한 터미널에서 **Ctrl+C**.

실행하면 터미널에 두 주소가 나옵니다.

- `http://127.0.0.1:8770`: 기본 화면.
- **막내 화면 주소**: 뒤에 긴 문자열이 붙은 전용 주소. 이 주소를 브라우저에서 엽니다.

막내 주소는 매 컴퓨터에서 새로 만들며 `.runtime/admin-url.txt`에도 저장합니다. 기본 주소만 열면 막내 화면으로 들어가지지 않는 것이 정상입니다.

## 3. 두 화면 써보기

1. 터미널에 나온 **막내 화면 주소**를 엽니다.
2. 조건표의 각 팀원 오른쪽 **개별 입력 ↗**를 누릅니다.
3. 참석 여부·메뉴·조용한 곳 선호·피해야 할 재료·도보 시간을 적고 저장합니다.
4. 막내 화면을 새로고침해 조건표와 후보 비교를 봅니다.
5. 한두 후보를 선택해 제안문을 만듭니다. 도구가 보내거나 확정하지는 않습니다.

팀원은 자신의 입력만 봅니다. 막내는 전체 조건표·비교·확인 질문을 봅니다. **막내가 제안하고 김 과장이 최종 승인**하는 설정입니다.

`127.0.0.1`은 실행한 컴퓨터만 가리킵니다. 다른 팀원이나 휴대폰에 이 주소를 보내 함께 사용하는 버전이 아닙니다. 공개 웹 배포는 이 저장소의 실행 절차에 포함하지 않았습니다.

## 4. 책의 확인 표로 시험하기

먼저 김 과장·박 대리·최 선배·한서윤의 가상 응답을 넣고 윤 선배는 비워둡니다. 도보는 최 선배 15분, 나머지 10분으로 넣습니다. 박 대리는 피해야 할 재료에 `새우`, 나머지는 `없음`을 적습니다. 김 과장은 한식과 조용한 곳 선호를 선택합니다.

| 시험 | 해볼 일 | 기대 결과 |
|---|---|---|
| T1 | D의 가격 20,000원 확인 | 원본은 **음료 포함 총액 미확인**. 가격만으로 통과시키지 않음 |
| T2 | C 확인 | 빈 가격을 추정하지 않고 가격 미확인 |
| T3 | 예산을 15,000원으로 변경 | 확정 후보가 없으면 확인할지 조건을 바꿀지 물음. 자동 완화 없음 |
| T4 | 박 대리가 새우 입력 | A·C의 재료 대응을 확인할 질문 표시 |
| T5 | 윤 선배 답을 넣지 않음 | 미확인자로 남기고 다시 물을 목록에 표시 |

음료까지 포함한 총액이 정확히 20,000원인 **별도 경계값 자료**의 비교도 자동 시험에 들어 있습니다. 원본 D를 음료 포함 가격으로 바꾸어 통과한 것처럼 만들지 않았습니다.

수정이 반영된 버전이므로 책의 수정 전 T3 실패 화면은 재현되지 않습니다. 대신 수정 후 질문을 확인할 수 있습니다.

```sh
npm test
```

비교·개인별 접근·제안문·접수 중단·응답 정리 등을 검사하는 20개 시험입니다. 실제 응답 저장 공간과 분리한 임시 메모리 DB를 쓰며 결과는 `.runtime/test-results/`에 남깁니다.

## 5. 저장과 정리

- 답은 내 컴퓨터의 `.runtime/preview.sqlite3`에 저장합니다. 종료 후 다시 실행해도 남습니다.
- `직전 설정 되돌리기`는 예산·마감 설정을 복원하며 응답을 되살리는 기능은 아닙니다.
- `응답 접수 중단`은 새 입력을 막고, `응답 접수 재개`로 다시 엽니다.
- `이번 주 응답 정리`는 응답을 지우고 이전 팀원 링크를 무효화하며 접수를 중단합니다. 다음 실습은 접수를 재개하고 새 개별 링크를 사용합니다.
- 완전히 새로 시작하려면 서버를 종료한 뒤 `.runtime` 폴더를 직접 지웁니다. **저장한 답과 막내 주소도 사라집니다.** 다시 실행하면 새로 만듭니다.

전용 링크를 가진 사람이 그 화면을 사용할 수 있습니다. 실제 사람의 민감한 정보를 넣지 말고 가상 자료로 실습하세요. 여기에는 책 제작 당시의 응답·운영 비밀키·배포 사이트 전용 링크가 없습니다.

## 코드 구성

| 경로 | 역할 |
|---|---|
| `web/` | 두 화면과 스타일 |
| `worker/api.js` | 정해진 비교·역할별 접근·제안문·정리 규칙 |
| `worker/restaurants.json` | 가상 식당 샘플. 자료에 없는 값은 null 또는 미확인 |
| `drizzle/0000_lunch_rooms.sql` | 로컬 저장 구조 |
| `scripts/` | 빌드·실행·20개 회귀 시험 |

웹 배포본과 같은 비교 규칙을 사용하되, 이 실습판은 클라우드 D1 저장 대신 Node.js의 SQLite 저장으로 실행합니다. AI 판단·투표·자동 알림·자동 발송·예약·결제는 없습니다.

### 실행이 안 될 때

- `node:sqlite`를 찾지 못하면 Node.js 버전을 확인합니다. 22.22.0 이상이 필요합니다.
- PowerShell에서 스크립트 실행 정책 오류가 나면 `npm.cmd start`를 사용합니다.
- 포트 8770이 이미 사용 중이면 먼저 실행한 점심 도우미를 종료하고 다시 실행합니다.
- Node.js의 SQLite 실험 기능 안내가 출력될 수 있습니다. 그 뒤 막내 화면 주소가 나오면 실행된 것입니다.
